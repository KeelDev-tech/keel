# Keel local state and canonical snapshot bridge

`keel_agent.state.LocalState` is a standard-library-only host boundary. It stores
bounded observations, private approval records, leased jobs and a durable event
outbox in SQLite. It performs no network calls, browser actions, model calls or
shell execution. Host code dispatches a fixed job-kind allowlist; payload text
is data and must never be interpreted as a command.

## Storage and trust

Create one database per canonical workspace. The constructor creates a missing
parent directory with mode `0700`; an existing parent must already be private.
Database and key files must be regular, owned files with mode `0600`, without
symlink or hardlink aliases. SQLite uses WAL and `synchronous=FULL`. Backups
must use SQLite's backup facility or a quiescent, properly checkpointed database;
copying only an open database file can omit WAL transactions. Back up its host
key with the database. An existing database with a missing or different key is
rejected rather than silently assigned a replacement key.

The random 32-byte host key is generated by `secrets.token_bytes`, held outside
model context, and signs HMAC-SHA256 snapshot envelopes. This proves possession
of the local host key. It does not authenticate the original queue producer,
prove statements true, identify a human approver, or create authority to submit
applications. Calls to `approve`, admission and reconciliation are trusted host
operations; a model must not be offered those functions as arbitrary tools.
The CLI is a single-user OS-account boundary, not a multi-tenant auth service.

The state database is the sole local authority for its workspace. Running two
independent databases for the same workspace would create separate dedupe
histories and is unsupported. Anyone controlling this OS account, key, database
or Python process can control this boundary. A coordinated rollback of the
entire database and key cannot be detected without a separate trusted monotonic
anchor. HMAC does not encrypt stored personal data. Use protected disks and
backups appropriate to the host; do not publish database or key files.

## Export, sign and import

The canonical exporter must produce a complete current queue observation and
complete attempt history. It must preserve real timestamps and source records;
it must not refresh timestamps on stale facts merely to pass a check.

```python
from datetime import datetime, timedelta, timezone
from keel_agent.state import LocalState

state = LocalState("/private/keel/state.db", "my-workspace")
now = datetime.now(timezone.utc)
# These are parsed, bounded current documents from the canonical exporter.
body = {"flow": flow_export, "assurance": assurance_export, "trust": trust_export}
envelope = state.sign_snapshot(
    body, flow_export["source_revision"], sequence=1,
    captured_at=now, expires_at=now + timedelta(seconds=90),
)
state.import_snapshot(envelope, now=now)
current = state.latest_snapshot(now=now)["body"]
```

`assurance` and `trust` may be absent from the supplied signing body; the signer
normalizes them to `null`. A normalized body has exactly those three keys.
Missing assurance is an observation gap, not approval. A runtime that requires
assurance must reject its absence during preflight. No import creates a queue
write or authorizes execution.

The envelope binds schema, workspace, source revision, contiguous sequence,
capture/expiry times, body digest, previous-envelope digest and host-key ID.
Imports verify the signature and all bindings inside the same transaction that
checks sequence history and appends the snapshot/event. The first sequence must
be `1`. Every subsequent sequence must be exactly the previous sequence plus
one, with the expected predecessor digest. Exact repeats are rejected as replay;
same-sequence different-digest imports are conflicts. Returning to an already
superseded source revision is rejected. Unseen source revisions are opaque
identifiers; the host exporter is responsible for their actual upstream order.

Expiry is at most 90 seconds after capture. Future, stale, incomplete exports
and incomplete attempt histories are rejected. The underlying flow and optional
assurance/trust schemas are validated; assurance binds the exact current flow
export and trust binds that flow plus the workspace. Business blockers remain
observations. The imported flow report is a diagnostic base-flow report, not a
combined approval decision. The v0.7 stable-scope evaluator must separately bind
reviewed material and apply every fresh execution gate before preparation or
fixture actions. Reads recheck current expiry and the stored HMAC/digest.

Successful state mutations persist a clock high-water mark; a subsequent
mutation or current-snapshot read with an earlier host time fails closed. The
clock is an aware datetime, ISO timestamp with offset, or finite nonnegative
Unix timestamp supplied by host code, never by model output.

## Durable work and fencing

The exact job kinds are `READ`, `REVIEW`, `PREPARE`, `SIMULATE`, `LOCAL_SUBMIT`.
`enqueue(kind, payload, idempotency_key=..., material_hash=..., now=...)` returns
the existing job only when the key, kind, payload and material hash all match.
A changed payload/material under the same idempotency key is rejected.

`claim(worker_id, now=..., lease_seconds=60, kinds=...)` atomically returns a job
with an incremented integer `token`. `heartbeat`, `complete` and `fail` require
that token and an unexpired lease. An expired worker cannot revive its lease or
write an outcome after another worker has claimed the job. The lease boundary
is exclusive: at exactly `lease_until`, ownership has expired.

Read, review, prepare and simulation jobs may be reclaimed after lease expiry.
An undispatched `LOCAL_SUBMIT` job can also be reclaimed because atomic admission
has not consumed an approval or allowed a browser action. Its former worker is
fenced. Once local dispatch is admitted, the job is `UNKNOWN` and never requeued
automatically, including after restart, timeout or failure. Explicit failures of
ordinary jobs are terminal; creating a retry requires a new host decision/key.

## Exact approval and local dispatch

Approvals bind the workspace implicitly through its database and explicitly
bind `role_id`, `material_hash`, `action`, `destination`, `account_id`. Only
`PREPARE` and `LOCAL_SUBMIT` are allowed actions. The host computes material_hash
over the exact approved document, answer/attachment bytes and relevant policy,
form, target and route revisions. A model-supplied hash is not evidence that
those bytes or revisions were checked. Approvals expire within 24 hours and may
be revoked. A consumed approval remains consumed, including after crashes.

For preparation, `consume_approval` is a one-use transition. A local submission
must use `admit_local_submit(job_id, token, approval_id, bindings, now=...)`.
That single transaction:

1. Checks the live fenced lease and exact job/payload/material bindings.
2. Checks the unused, current, unrevoked approval against every binding.
3. Acquires a workspace/role hold even if another job has different material or
   destination. Unknown and confirmed role outcomes both prevent a duplicate.
4. Consumes approval, marks the job `UNKNOWN`, and appends durable events.

Only after successful commit may host code call its local fixture browser
adapter. The browser adapter must independently enforce its loopback fixture
allowlist and exact page/receipt checks. This API is not an internet submission
capability. Revocation after admission cannot undo an action already in flight.

`complete` for an admitted local job requires trusted host evidence containing:

```json
{
  "job_id": "job returned by enqueue",
  "role_id": "exact approved role",
  "material_hash": "64 lowercase hex characters",
  "action": "LOCAL_SUBMIT",
  "destination": "exact approved local fixture URL",
  "account_id": "exact approved fixture account",
  "outcome": "CONFIRMED_LOCAL",
  "external_submission": false,
  "evidence_ref": "reference to verified fixture receipt",
  "evidence_sha256": "SHA256 of the actual verified browser receipt"
}
```

Every binding and job ID is checked. The host must verify the referenced receipt
and calculate its digest; an arbitrary reference/hash is not proof. For a lost
response, `reconcile_local(job_id, evidence, outcome, now=...)` accepts the same
binding fields and only `NOT_SENT` or `CONFIRMED_LOCAL`. It is a trusted host
operation over an existing `UNKNOWN` dispatch. `NOT_SENT` releases the role hold
but never restores the consumed approval. A new attempt requires a new job and
new approval. Ambiguous evidence must remain `UNKNOWN`.

## Event outbox

`events(after=0, limit=100)` returns stable random event IDs and monotonic SQLite
sequence numbers, ordered by sequence, with workspace IDs. Events are appended
in the same transaction as the corresponding transition; failed transactions
leave neither partial state changes nor events. The canonical log consumer
should persist its last acknowledged cursor and deduplicate by `event_id`.
Repeated export is intentional and must not create duplicate canonical events.
The module does not rewrite the canonical queue or silently delete local events.
