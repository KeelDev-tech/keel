# Supply acceptance as a release check

Run `python -S tools/run_supply_acceptance.py --out /tmp/keel-supply-acceptance-UNIQUE` from a source checkout or the verified extracted package. The output directory must be new and outside the source tree. The command uses only the standard library, synthetic applicant data, injected public-board responses and fixture host observations. It requires no paid services or model calls.

The 23 checks exercise the actual production supply planner, posting verifier, queue transactions, event outbox, packet sealing/admission and interrupted-run reconciliation. A normal case verifies an exact posting, prepares a scoped material packet, and observes one preparation gain per recorded reader dispatch. It leaves the queue status unchanged and launch authority unknown. Separate cases preserve applicant questions and ledger history, retain prior LIVE evidence after HTTP 429, stop after one rate-limited dispatch, preserve dry-run bytes, refuse a commit after host ownership changes, and block replay of an interrupted canary.

An injected posting contains instructions to clear office holds and submit applications. The deterministic posting path preserves the held row; this check does not establish a model's resistance to prompt injection. No model or browser is exercised. Authenticated production Muse integration and production supply recovery remain unverified.

`acceptance.json` records the fixture evidence, checks and actual counters. Its source digest covers all reviewed `release-files.json` payload members, including this runner and its tests; it is a source binding, not an authenticity signature. CLI execution uses a Python audit hook to prohibit network and child-process attempts and counts attempted calls even if an exception is caught. This guard is not an OS sandbox. Output contains synthetic evidence only and must not be treated as a template for logging real applicant answers.

The recovery CI workflow runs this command as a release prerequisite and retains the report for review. Tests independently alter observed state, holds, dispatch counts, replay outcomes and authority claims to prove that the grader rejects false success. A child-process regression attempts to create a socket, catches the guard exception, and still receives a FAIL report and nonzero exit. The extracted-profile smoke test runs the same command with site packages disabled. This adds supply-specific coverage to the existing Muse and operational acceptance runners; it does not replace them or imply a fully green broad legacy suite.

This adopts the useful parts of the supplied *Building Keel: agentic-system state of the art and practical implications* report: deterministic authority, explicit postconditions, durable recovery, actual resource accounting and source-bound acceptance before expanding autonomy. Further model routing, persistent memory or delegation should depend on measured gains on Keel tasks.
